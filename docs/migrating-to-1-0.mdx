---
title: Migrating to 1.0
description: Move an app from @adonis-agora/media 0.x to 1.0. The media and React APIs are unchanged; the console is closed in production until you set authorize, and its standalone provider is gone.
icon: ArrowUpCircle
---

`@adonis-agora/media` 1.0 keeps the 0.30 media API as it is, and so does `@adonis-agora/media-react` 1.0. The changes are all in the console: its pages and API answer `403` in production until `config/media_dashboard.ts` sets `authorize`, `@adonis-agora/media-dashboard` 10 no longer ships its standalone provider (register the console from `@adonis-agora/media`), and the console reads its runtime config only from the data block the provider injects.

---

## Requirements

- **Node.js 24 or later.** `engines.node` is `>=24`, the same line AdonisJS 7 requires. 1.0 is tested on Node 24 and 26.
- **AdonisJS 7** (`@adonisjs/core` `^7.3.0`), unchanged.
- **`@adonisjs/drive` `^3.0.0` or `^4.0.0`**, unchanged.

If your app already runs on AdonisJS 7, it already runs on Node 24 or later.

---

## Upgrade

1.0 is published first as a release candidate under the `rc` tag:

```sh
npm i @adonis-agora/media@rc @adonis-agora/media-react@rc
```

Once 1.0.0 is final, install it as usual:

```sh
npm i @adonis-agora/media@^1.0.0 @adonis-agora/media-react@^1.0.0
```

If `@adonis-agora/media-dashboard` is in your `package.json` only to register its provider, remove it after the change below:

```sh
npm uninstall @adonis-agora/media-dashboard
```

---

## Breaking changes

### The console is closed in production until you set `authorize`

Without `authorize`, the media console used to be open to every request unless `middleware` or
`auth` closed it. In 1.0 it is open only outside production. In production its pages and API answer
`403` until `config/media_dashboard.ts` sets `authorize`, and a warning at boot says so.
`authorize` runs before `middleware`, so a console guarded only by `middleware` is refused too.

Before:

```ts title="config/media_dashboard.ts"
import { defineConfig } from '@adonis-agora/media/dashboard'
import { middleware } from '#start/kernel'

export default defineConfig({
  middleware: middleware.admin(),
})
```

After, with the check in `authorize`:

```ts title="config/media_dashboard.ts"
import { defineConfig } from '@adonis-agora/media/dashboard'

export default defineConfig({
  authorize: (ctx) => ctx.auth.user?.isAdmin === true,
})
```

Or keep your middleware and open the first gate explicitly:

```ts title="config/media_dashboard.ts"
import { defineConfig } from '@adonis-agora/media/dashboard'
import { middleware } from '#start/kernel'

export default defineConfig({
  authorize: () => true,
  middleware: middleware.admin(),
})
```

Apps that already set `authorize` need no change. `authorize` now also accepts a class with an
`authorize(ctx)` method, built through the container, or a lazy import of one, and a
`{ redirectTo: '/login' }` answer. See [Console access](/docs/media/dashboard/authentication).

### Console refusals answer lowercase JSON

The console API's refusal bodies now match every other Agora console.

Before:

```json
{ "error": "Forbidden" }
{ "error": "Unauthorized" }
```

After:

```json
{ "error": "forbidden" }
{ "error": "unauthenticated" }
{ "error": "unauthenticated", "redirectTo": "/login" }
```

The last one answers an API call when `authorize` returns `{ redirectTo }`. Update any client that
matches on the old strings.

### The console access types are renamed

The types for `authorize` are now the ones every Agora console shares.

| 0.x | 1.0 |
| --- | --- |
| `DashboardAuthorize` | `ConsoleAuthorize` |
| `AuthorizeResult` | `ConsoleAuthorizeResult` |
| `AuthorizeDecision` | `ConsoleAuthorizeResult` (its object members) |

Before:

```ts
import type { DashboardAuthorize } from '@adonis-agora/media/dashboard'
```

After:

```ts
import type { ConsoleAuthorize } from '@adonis-agora/media/dashboard'
```

### The console's own login (`auth`) is removed

The console no longer has a login of its own. The `auth` option of `config/media_dashboard.ts` is
removed, with no alias, and with it:

- the console's login screen and its **sign out** button;
- the `GET <apiBasePath>/me`, `POST <apiBasePath>/login`, `POST <apiBasePath>/session` and
  `POST <apiBasePath>/logout` routes, and the `media_dashboard_session` cookie;
- the `secret`, `ttl`, `session`, `login` and `revalidate` hooks;
- the exports `resolveConsoleAuth`, `signSessionCookie`, `verifySessionCookie` and the types
  `ConsoleAuthOptions`, `ResolvedConsoleAuth`, `ConsoleSession`, `ConsoleSessionUser`,
  `ConsoleSessionUserInfo`, `AuthMode`, `SessionHook`, `LoginHook`, `RevalidateHook`, `MeResponse`
  and `LoginBody` (from `@adonis-agora/media/dashboard` and `@adonis-agora/media-dashboard`);
- the console launcher in `@adonis-agora/media-react`: `OpenMediaDashboardButton`,
  `useOpenMediaDashboard`, `openMediaDashboardMutationOptions`, `openMediaDashboard`,
  `mintMediaDashboardSession`, `mediaDashboardSessionUrl`, `mediaDashboardUrl`,
  `ConsoleSessionError` and their types. A plain link to the console's `basePath` replaces it.

Operators sign in through your app. Gate the console in `authorize`, and return
`{ redirectTo: '/login' }` for a signed-out visitor: a page navigation is redirected there, and the
console follows the same `redirectTo` when one of its API calls answers `401` (without one, it
reloads the page). Remove the secret and password variables you added for `auth` from `start/env.ts`.

Before:

```ts title="config/media_dashboard.ts"
import env from '#start/env'
import User from '#models/user'
import { defineConfig } from '@adonis-agora/media/dashboard'

export default defineConfig({
  authorize: () => true,
  auth: {
    secret: env.get('MEDIA_DASHBOARD_SECRET'),
    ttl: '8h',
    login: async (username, password) => {
      const user = await User.verifyCredentials(username, password).catch(() => null)
      if (!user?.isAdmin) return null
      return { id: String(user.id), name: user.fullName }
    },
  },
})
```

```tsx
<OpenMediaDashboardButton headers={() => ({ Authorization: `Bearer ${token()}` })} />
```

After:

```ts title="config/media_dashboard.ts"
import { defineConfig } from '@adonis-agora/media/dashboard'

export default defineConfig({
  authorize: async (ctx) => {
    if (!(await ctx.auth.check())) return { redirectTo: '/login' }
    return ctx.auth.user!.isAdmin === true
  },
})
```

```tsx
<a href="/media/dashboard">Open Media console</a>
```

### The standalone console provider is removed

`@adonis-agora/media-dashboard` no longer ships a provider: the `@adonis-agora/media-dashboard/media_dashboard_provider` subpath and the `MediaDashboardProvider` export are gone. The console ships in `@adonis-agora/media`; register its provider instead. `config/media_dashboard.ts` stays as it is.

Before:

```ts title="adonisrc.ts"
providers: [
  () => import('@adonis-agora/media/media_provider'),
  () => import('@adonis-agora/media-dashboard/media_dashboard_provider'),
]
```

After:

```ts title="adonisrc.ts"
providers: [
  () => import('@adonis-agora/media/media_provider'),
  () => import('@adonis-agora/media/dashboard_provider'),
]
```

`@adonis-agora/media-dashboard` still exports the console's API types, so a browser bundle can keep importing them:

```ts
import type { DiskInfo, ObjectListResponse } from '@adonis-agora/media-dashboard/types'
```

It no longer has peer dependencies, so installing it no longer requires `@adonis-agora/media` or `@adonisjs/core`.

### The console no longer reads `window.__MEDIA_DASHBOARD__`

The provider passes the console its runtime config as a JSON data block in `index.html`, and that block is now the only source. If you served the console's HTML yourself and set the global, emit the block instead.

Before:

```html
<script>
  window.__MEDIA_DASHBOARD__ = { apiBase: '/ops/media/api' }
</script>
```

After:

```html
<script type="application/json" id="media-dashboard-config">
  { "apiBase": "/ops/media/api" }
</script>
```

Apps that let the provider serve the console need no change.

### Everything else works unchanged

Code like this works on 1.0 exactly as it did on 0.30:

```ts title="app/controllers/avatars_controller.ts"
import { createReadStream } from 'node:fs'
import media from '@adonis-agora/media/services/main'
import type { HttpContext } from '@adonisjs/core/http'

export default class AvatarsController {
  async update({ request, response, auth }: HttpContext) {
    const user = auth.getUserOrFail()

    const avatar = request.file('avatar', { size: '2mb', extnames: ['jpg', 'jpeg', 'png', 'webp'] })
    if (!avatar) return response.badRequest({ error: 'An "avatar" file is required' })

    const att = await media.attachments.createFromFile(
      {
        fileName: avatar.clientName,
        mimeType: avatar.type!,
        contents: createReadStream(avatar.tmpPath!),
      },
      { variants: [{ name: 'thumb', width: 100 }] },
    )

    user.avatarData = att.toJSON()
    await user.save()

    return response.ok(user)
  }
}
```

## Other @adonis-agora packages

The optional integrations now accept both 0.x and 1.x of the packages they work with, so you can move each one to 1.0 on its own schedule:

| Peer                           | Accepted range       |
| ------------------------------ | -------------------- |
| `@adonis-agora/authz`          | `>=0.16.0 <2.0.0 \|\| >=1.0.0-rc.0 <2.0.0` |
| `@adonis-agora/authkit-client` | `>=0.18.0 <2.0.0 \|\| >=1.0.0-rc.0 <2.0.0` |
| `@adonis-agora/authkit-server` | `>=0.60.0 <2.0.0 \|\| >=1.0.0-rc.0 <2.0.0` |
| `@adonis-agora/telescope`      | `>=0.4.0 <2.0.0 \|\| >=1.0.0-rc.0 <2.0.0`  |

The second clause in each range admits the 1.0 release candidates, so you can mix `rc` packages without peer warnings.
