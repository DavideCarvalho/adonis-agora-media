The console has no login of its own. Operators sign in through your app, and the console asks
`authorize` whether the signed-in request may open it. `authorize` is the same access option every
`@adonis-agora` console takes (telescope, durable, payments, agent, the authkit admin). It runs
**before** `middleware` (both must pass) and comes in three forms.

An inline function, which receives the `HttpContext`:

```ts title="config/media_dashboard.ts"
import { defineConfig } from '@adonis-agora/media/dashboard'

export default defineConfig({
  authorize: (ctx) => ctx.auth.user?.isAdmin === true,
})
```

A helper that returns one, such as `authorizeByRoles` from `@adonis-agora/authz`:

```ts title="config/media_dashboard.ts"
import { defineConfig } from '@adonis-agora/media/dashboard'
import { authorizeByRoles } from '@adonis-agora/authz'

export default defineConfig({
  authorize: authorizeByRoles({ roles: ['ADMIN'] }),
})
```

A class in its own file, passed directly or as a lazy import. It is built through the container,
so `@inject()` dependencies work, and the same class works for every Agora console:

```ts title="app/policies/console_access.ts"
import { inject } from '@adonisjs/core'
import type { HttpContext } from '@adonisjs/core/http'
import type { ConsoleAuthorizer } from '@adonis-agora/media/dashboard'
import AuditService from '#services/audit_service'

@inject()
export default class ConsoleAccess implements ConsoleAuthorizer {
  constructor(private audit: AuditService) {}

  async authorize(ctx: HttpContext) {
    const user = ctx.auth.user
    if (!user) return { redirectTo: '/login' }
    await this.audit.record('media-console.open', user.id)
    return user.isAdmin
  }
}
```

```ts title="config/media_dashboard.ts"
import { defineConfig } from '@adonis-agora/media/dashboard'

export default defineConfig({
  authorize: () => import('#policies/console_access'),
  // or: import ConsoleAccess from '#policies/console_access' and pass `authorize: ConsoleAccess`
})
```

The check answers with a `ConsoleAuthorizeResult` (exported from `@adonis-agora/media/dashboard`
with `ConsoleAuthorize`, `ConsoleAuthorizer` and `authorizeByToken`):

| The check returns | API request | Page navigation |
| --- | --- | --- |
| `true` / `{ allowed: true }` | passes | passes |
| `{ redirectTo: '/login' }` | `401 { error: 'unauthenticated', redirectTo: '/login' }` | `302` to that path |
| `{ allowed: false, reason: 'unauthenticated' }` | `401 { error: 'unauthenticated' }` | the [access-denied page](#the-access-denied-page), `401` "Sign in required" |
| `{ allowed: false, reason: 'forbidden' }` | `403 { error: 'forbidden' }` | the access-denied page, `403` |
| `false` / `{ allowed: false }` (no reason) | `403 { error: 'forbidden' }` | the access-denied page, `403` |
| throws | `403 { error: 'forbidden' }` | the access-denied page, `403` |

### Machine access with a token

For scripts and monitoring, `authorizeByToken` allows a request that sends
`Authorization: Bearer <token>` and answers `401` to anything else. It reads the header only. An
empty or missing token throws when the config loads, so a forgotten env var never opens the console.

```ts title="config/media_dashboard.ts"
import env from '#start/env'
import { authorizeByToken, defineConfig } from '@adonis-agora/media/dashboard'

export default defineConfig({
  authorize: authorizeByToken({ token: env.get('CONSOLE_TOKEN') }),
})
```

```sh
curl -H "Authorization: Bearer $CONSOLE_TOKEN" https://app.example.com/media/dashboard/api/disks
```

To let both operators and scripts in, pass both to `anyAuthorize`. It allows a request when any of
them does, tried in order:

```ts title="config/media_dashboard.ts"
import env from '#start/env'
import { anyAuthorize, authorizeByToken, defineConfig } from '@adonis-agora/media/dashboard'

export default defineConfig({
  authorize: anyAuthorize(
    authorizeByToken({ token: env.get('CONSOLE_TOKEN') }),
    (ctx) => ctx.auth.user?.isAdmin === true,
  ),
})
```

### Sending signed-out visitors to your login

Return `{ redirectTo }` for a request with no signed-in user. A page navigation is redirected there,
and when one of the console's API calls answers `401` mid-session (the user signed out in another
tab), the console follows the same `redirectTo`. A `401` without one makes the console reload the
page, so the server answers the navigation itself.

```ts title="config/media_dashboard.ts"
import { defineConfig } from '@adonis-agora/media/dashboard'

export default defineConfig({
  authorize: async (ctx) => {
    if (!(await ctx.auth.check())) return { redirectTo: '/login' }
    return ctx.auth.user!.isAdmin === true
  },
})
```

### Without `authorize`

When `authorize` is not set, the console is open outside production (`node ace serve`, tests),
and in production it answers `403` to every page and API request. Either way, it logs this once
at boot:

```txt
[@adonis-agora/media] console has no `authorize` configured: it is open outside production and denies every request in production. Set `authorize` in config/media_dashboard.ts.
```

Set `authorize` before you deploy. If `middleware` already decides who gets in, open the first gate
explicitly:

```ts title="config/media_dashboard.ts"
import { defineConfig } from '@adonis-agora/media/dashboard'
import { middleware } from '#start/kernel'

export default defineConfig({
  authorize: () => true,
  middleware: middleware.admin(),
})
```

An answer the check writes itself (for example `ctx.response.redirect(...)` before returning
`false`) is left as it is.

### The access-denied page

What a browser sees when `authorize` refuses it: the same `401`/`403` the API answers with, as a page
— a dark card in the console's visual language showing the status, a sentence explaining the
refusal and a "Back to app" link.
It carries no inline script, so a nonce'd `script-src` CSP cannot break it (its one inline
`<style>` picks up `@adonisjs/shield`'s request nonce).

Tweak it with `accessDenied` — every field optional:

```ts title="config/media_dashboard.ts"
export default defineConfig({
  authorize: authorizeByRoles({ roles: ['ADMIN'] }),
  accessDenied: {
    brand: 'Entre Textos',           // eyebrow + <title>; default "Media"
    title: 'Sem acesso',             // default "Access denied"
    message: 'Peça ao admin para liberar o console de mídia.',
    homeHref: '/admin',              // "Back to app"; default "/", `false` hides it
    homeLabel: 'Voltar',
    accent: '#f59e0b',               // any CSS colour; default: the console's cyan
  },
})
```

Or replace it. Pass a function and it receives the refusal (`status`, `reason`, `basePath`, and
the CSP `nonce` when there is one) plus the `HttpContext`. Return an HTML string to have it
served with the right status; answer the request yourself and return nothing to make the
provider stand down:

```ts title="config/media_dashboard.ts"
export default defineConfig({
  accessDenied: (info, ctx) => {
    ctx.response.redirect(`/login?next=${encodeURIComponent(info.basePath)}`)
  },
})
```

<Callout type="info" title="They compose">
  `authorize` and `middleware` are independent gates on the same routes. Configure both and a
  request must pass both, `authorize` first.
</Callout>
