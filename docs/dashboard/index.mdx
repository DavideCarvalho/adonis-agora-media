**The management console** for your media: browse your buckets, watch resumable uploads in progress, upload new objects, and copy / move / delete objects across buckets. It's a small React SPA served by a thin AdonisJS provider, themed to Agora design tokens (light + dark).

Nothing about storage is reimplemented: the console consumes the **real** media surface — disk `list` / `stat` / `copy` / `move` / `deleteMany` (from the [S3 disk](/docs/media/storage/s3-disk)'s extended operations) and the resumable [`UploadSessionStore.list()`](/docs/media/uploads/resumable-tus) — through provider-registered routes, and reuses [`@adonis-agora/media-react`](/docs/media/react) for the upload UI.

<Callout type="info" title="Ships embedded — no separate install">
  The console is built into `@adonis-agora/media` itself. `node ace configure @adonis-agora/media` registers its provider for you — nothing else to add.
</Callout>

---

## Install

```ts title="adonisrc.ts"
providers: [
  () => import('@adonis-agora/media/media_provider'),
  () => import('@adonis-agora/media/dashboard_provider'),
]
```

`node ace configure @adonis-agora/media` does this for you automatically, alongside publishing `config/media_dashboard.ts`.

## Configure — `config/media_dashboard.ts`

```ts title="config/media_dashboard.ts"
import { defineConfig } from '@adonis-agora/media/dashboard'
import { middleware } from '#start/kernel'

export default defineConfig({
  basePath: '/media/dashboard',   // where the SPA mounts (default)
  actions: true,                  // enable copy/move/delete (default: false — read-only)
  disks: ['s3', 'backups'],       // browsable disks (default: derived from media config)
  authorize: (ctx) => ctx.auth.user?.isAdmin === true, // who may open it — SPA + API
  middleware: middleware.auth(),  // runs after authorize
})
```

| Key | Type | Default | What it controls |
|-----|------|---------|------------------|
| `basePath` | `string` | `/media/dashboard` | Where the SPA is mounted. |
| `apiBasePath` | `string` | `<basePath>/api` | Where the JSON API is mounted. |
| `actions` | `boolean` | `false` | Enable mutating actions (copy / move / delete). Off = read-only browser. |
| `disks` | `string[]` | derived from media config | Disk names the console may browse / act on. |
| `uploadsPrefix` | `string` | `/media/uploads` | Match `media.uploads.routes.prefix`. |
| `tusPrefix` | `string` | `/media/uploads/tus` | Match `media.uploads.resumable.routes.prefix`. |
| `authorize` | `ConsoleAuthorize` | open outside production, `403` in production | Who may open the console (SPA + API): a function, a class or a lazy import. See [Console access](/docs/media/dashboard/authentication). |
| `accessDenied` | object or function | built-in page | What a browser sees when `authorize` refuses a page navigation. |
| `middleware` | handler(s) | — | Host middleware applied to the whole console (SPA + API), after `authorize`. |
| `enabled` | `boolean` | `true` | Mount the console at all. `false` registers the provider — so its config type stays available — without exposing a single route. |
| `objectInsights` | `ObjectInsightProvider[]` | `[]` | Host-supplied annotations rendered in the object preview. See [below](#object-insights). |
| `objectUrls` | `'auto' \| 'proxy'` | `'auto'` | Where the `url` reported for an object's bytes points — the store (signed), or this console's own `/object/raw`. See [below](#object-urls). |
| `viewer` | `(ctx) => { label, email?, role? } \| null` | `ctx.auth.user` | Who the sidebar footer shows as signed in. See [Signed-in user and sign-out](#signed-in-user-and-sign-out). |
| `signOut` | path, `{ href }` or `false` | announced by authkit | The sidebar footer's sign-out: a POST action path, a link, or none. |

`enabled: false` is the per-environment switch: keep the provider registered (and `config/media_dashboard.ts` type-checked) in every environment, and let the config decide where the console actually exists. It short-circuits in `boot()`, before any route is registered — not a 403, simply nothing mounted.

<Callout type="warn">
  The console is a read-only browser by default. Flipping `actions: true` enables copy / move / delete, folder operations, record deletion, upload aborts and the console upload — decide who may open the console with `authorize` (plus `middleware` if you like) before you do. Without `authorize`, the console's pages and API answer `403` in production. Mounting the SPA under any `basePath` needs no rebuild: the provider rewrites Vite's asset base and injects the runtime config into `index.html` as a JSON data block (`<script type="application/json" id="media-dashboard-config">`) at serve time. A data block is never executed, so a strict Content-Security-Policy (shield's `@nonce`) does not block it.
</Callout>

## Routes

The provider registers a JSON API under `apiBasePath` (default `<basePath>/api`). Every route runs behind `authorize` and then your `middleware`. The console has no login routes: sign-in is your app's own.

| Method | Path | Backed by |
|--------|------|-----------|
| `GET` | `/topology` | capability probe (`{ disks, hasUploads, actions }`) |
| `GET` | `/consoles` | the other Agora consoles this viewer may open ([switcher](#switching-between-consoles)) |
| `GET` | `/consoles/search?q=` | search across those consoles and this one |
| `GET` | `/disks` | `StorageManager` + `DiskCapabilities` |
| `GET` | `/objects?filter[disk]&filter[prefix]&after&first` | disk `list` ([list routes](#list-routes)) |
| `GET` | `/object?disk&key` | disk `stat` + the object's `url` (signed, or the proxy — see [`objectUrls`](#object-urls)) |
| `POST` | `/object?disk&key&type` | raw-body object upload (the console's convenience upload) — `actions` only |
| `GET` | `/object/raw?disk&key` | streams the object's bytes through the app, `content-disposition: inline` |
| `GET` | `/object/insights?disk&key` | the registered [object-insight providers](#object-insights) |
| `GET` | `/uploads?filter[disk]&filter[prefix]&sort` | `ResumableUploadManager.list()` ([list routes](#list-routes)) |
| `GET` | `/uploads/:id` | one session in full, plus its recorded parts |
| `POST` | `/uploads/:id/abort` | discard an in-flight session — `actions` only |
| `GET` | `/collections?filter[collection]&filter[ownerType]&filter[ownerId]&filter[prefix]&after&first` | `MediaStore.list` ([list routes](#list-routes); see [Collections view](/docs/media/dashboard/collections)) |
| `GET` | `/collections/summary` | per-collection rollup (count + total bytes) for the filter chips |
| `GET` | `/media-record?id` | one `MediaRecord` plus a signed URL per conversion |
| `POST` | `/media-record/delete` | `MediaStore.delete` — `actions` only |
| `POST` | `/copy` · `/move` | disk `copy` / `move` (streamed for cross-disk) — `actions` only |
| `POST` | `/delete` | disk `deleteMany` — `actions` only |
| `POST` | `/folder` | create a zero-byte folder marker — `actions` only |
| `POST` | `/folder/delete` | recursively delete a folder — `actions` only |
| `POST` | `/folder/copy` · `/folder/move` | recursively copy / move a folder (same or cross disk) — `actions` only |

The `actions`-only routes are always *mounted*; the gate is enforced one layer down, in `DashboardService`, which throws a `403` when `actions` is false. So a read-only console needs no conditional routing — the routes exist and refuse.

Two upload paths coexist, on purpose. `POST /object` is the console's own convenience upload: raw bytes as `application/octet-stream` (so your app's body parsers never consume the stream), the real MIME riding as the `type` query param, buffered in memory and therefore capped at 100 MB. Anything larger belongs on the core `@adonis-agora/media` TUS / direct routes, which the console drives through `@adonis-agora/media-react`.

`GET /object/raw` exists for the preview: a signed URL is fine for an image tag, but streaming through the app is what lets the lightbox read a text/CSV body without a cross-origin fetch, and what works at all on a disk the browser cannot reach directly.

## List routes

The list routes speak the [`@adonis-agora/filter`][filter] list format, like every
`@adonis-agora/*` console.

| Route | Filters | Sort | Paging |
|---|---|---|---|
| `GET /objects` | `filter[disk]` (required), `filter[prefix]` | `key` only | cursor, `first` up to 1000 (default 1000) |
| `GET /collections` | `filter[collection]`, `filter[ownerType]`, `filter[ownerId]`, `filter[prefix]` | `-createdAt` only | cursor, `first` up to 200 (default 50) |
| `GET /uploads` | `filter[disk]`, `filter[prefix]` | `createdAt` or `-createdAt` (default) | none |
| `GET /disks`, `GET /collections/summary` | none | none | none |

An unknown filter field, an operator other than equality, or a sort outside the column above is
answered with `400`.

```http
GET /media/dashboard/api/objects?filter[disk]=s3&filter[prefix]=photos/&first=100
GET /media/dashboard/api/collections?filter[collection]=avatar&after=eyJ…&first=50
```

Paged routes answer `{ data, meta }`; the others answer `{ data }`:

```jsonc
{
  "data": [
    { "type": "folder", "name": "2024", "prefix": "photos/2024/" },
    { "type": "file", "key": "photos/a.jpg", "name": "a.jpg", "sizeBytes": 1024, "lastModified": "…" }
  ],
  "meta": {
    "nextCursor": "eyJ…", // send it back as ?after= — null on the last page
    "prevCursor": null,
    "hasNext": true,
    "hasPrev": false
  }
}
```

`/objects` returns folders first, then files, each row tagged with `type`. `/collections` returns
`MediaEntry` rows, newest first.

<Callout type="warn" title="Forward only">
  The listings page forward only: S3's continuation token and the media store's newest-first keyset
  cannot step back. `before` and `last` are answered with `400`, `prevCursor` is always `null` and
  `hasPrev` always `false`. Keep the pages you have already loaded, as the console does.
</Callout>

The cursor is opaque: send `meta.nextCursor` back as `after` as it is.

[filter]: https://github.com/DavideCarvalho/adonis-agora-filter

## Object URLs

Every object the console shows has a `url`: what "Open ↗" links to, and what the image / video / audio previews set as their `src`. By default (`objectUrls: 'auto'`) that is a short-lived **signed URL straight to the object store** — a real link, one that survives a copy-paste out of the console and needs nothing from your app to resolve.

That default assumes the browser can reach the store. On a deployment where it cannot — a private bucket on an internal network, a MinIO addressed by an in-cluster hostname, a policy against client-to-bucket traffic — the signed URL is minted against the **internal** endpoint and resolves nowhere in a browser (`ERR_NAME_NOT_RESOLVED`, or a CORS wall). Set `objectUrls: 'proxy'` and the console reports its own same-origin `<apiBasePath>/object/raw` instead, so every byte travels through your app, under the same auth as the rest of the console:

```ts title="config/media_dashboard.ts"
export default defineConfig({
  basePath: '/media',
  objectUrls: 'proxy',
})
```

The trade-off is the mirror image of the default: a proxied URL only means something to a session that can reach your app, and your app pays the bandwidth. The PDF and text previews are unaffected either way — they always read through `/object/raw`, because rendering them needs same-origin bytes.

When `objectUrls` is unset, the console follows your core media config: `delivery.mode: 'proxy'` in `config/media.ts` implies `'proxy'` here — a host already streaming every read through the app has declared its store unreachable from a browser, so the console does the same without being told twice. Anything else keeps `'auto'`. An explicit `objectUrls` always wins over the delivery mode.

This is the same option, with the same two values, as the NestJS sibling console.

## Folder operations

Object stores are flat key spaces with no real directories — a "folder" is just the `/`-delimited prefix that delimiter listing rolls keys up under. The console makes that browsable and editable through four `actions`-gated routes. All take a JSON body with a `disk`; copy/move add `from` / `to` (and an optional `toDisk` to cross disks).

| Route | Body | Behaviour |
|-------|------|-----------|
| `POST /folder` | `{ disk, prefix }` | **Create.** Writes a zero-byte marker object at `<prefix>/`, which delimiter listing then surfaces as a navigable, empty folder. The prefix is normalized to exactly one trailing slash (no double-slash keys); an empty prefix is rejected `400`. |
| `POST /folder/delete` | `{ disk, prefix }` | **Recursive delete.** Sweeps every object under `<prefix>/` — nested included — with an *empty* delimiter so the driver lists keys flat, paginates until the bucket is exhausted, `deleteMany`s each page, then removes the marker itself. |
| `POST /folder/copy` | `{ disk, from, to, toDisk? }` | **Recursive copy.** Relocates every key under `<from>/` to `<to>/`, preserving each key's path relative to the source, and writes the destination marker. The source is left intact. |
| `POST /folder/move` | `{ disk, from, to, toDisk? }` | **Recursive move.** Same recursive relocation, then drops the source objects and marker. |

The recursive copy/move share one engine with the single-object [`/copy` · `/move`](#routes): each key transfers **same-disk** via the driver's native server-side `copy` / `move` (no bytes through the app), or **cross-disk** by streaming get→put through the app (drivers can't copy across disks), capped per object at 100 MB. A same-disk move/copy whose destination sits *inside* the source is rejected `400` (it would recurse forever); across disks that can't happen.

<Callout type="warn" title="Folder actions need `actions: true`">
  Like copy / move / delete, every folder route is gated on `actions: true` and returns `403` when the console is read-only. Recursive delete and move are destructive and irreversible — keep the whole console behind your `middleware` auth guard.
</Callout>

## Object insights

The console can only describe a file the way storage sees it: key, size, content type, last modified. Everything that makes the file *mean* something — which work order this scan belongs to, which knowledge base indexed it, who uploaded it — lives in your app.

`objectInsights` is the seam for handing that back. You register providers; the console asks them whenever an object is previewed and renders whatever comes back:

```ts title="config/media_dashboard.ts"
import { defineConfig } from '@adonis-agora/media/dashboard'
import Document from '#models/document'

export default defineConfig({
  objectInsights: [
    {
      id: 'documents',
      async resolve({ disk, key }) {
        const doc = await Document.findBy('storageKey', key)
        if (!doc) return null // nothing to say about this object

        return {
          title: 'Document',
          facts: [
            { label: 'Title', value: doc.title },
            { label: 'Owner', value: doc.ownerEmail },
            { label: 'Indexed', value: doc.indexedAt?.toISO() ?? 'not yet' },
          ],
          links: [{ label: 'Open in app', href: `/documents/${doc.id}` }],
          note: 'Deleting this object leaves the document row orphaned.',
        }
      },
    },
  ],
})
```

Three properties of the design are worth being explicit about:

- **Data, not components.** The console ships as a prebuilt SPA bundle, so a host cannot inject React into it. A provider returns a small structured value (`facts`, `links`, a `note`) the console knows how to render.
- **Failures are invisible.** A provider that throws is skipped and logged; providers run concurrently so one slow lookup doesn't serialize the rest. Annotation must never be able to stop an admin opening a file.
- **Links are sanitized.** Every insight passes through `sanitizeInsight` before it reaches the browser: a relative `/…` href is kept, an absolute one only if it is `http:`/`https:`. `javascript:`, `data:` and protocol-relative `//evil.com` are dropped, not rendered.

`resolve` runs on **every preview of every object**, so keep it cheap — a single indexed lookup, not a fan-out.

## Views

The sidebar has two groups. **Library** holds Library and Collections. **Transfers** holds Uploads and Upload. The topbar holds the organization picker (with [tenancy](/docs/media/tenancy) on), the disk count, whether resumable uploads and actions are on, and ⌘K search. Below 768px the sidebar opens as a drawer. The console has a light and a dark theme, remembered per browser.

- **Library** — the disk browser. A lazy, collapsible **folder tree** in the left rail (each disk is a root; expanding a node fetches only that level, and every node is a drop target for drag-to-move), the object list in the main pane with cursor-paginated `list`, and create / copy / move / delete for folders and objects across buckets (see [Folder operations](#folder-operations)).
- **Lightbox** — clicking an object opens a modal preview that renders by content type: images, video, audio, PDFs, and text/JSON/CSV/TSV (tabular formats as a real table); anything else falls back to an "open original" link. The [object insights](#object-insights) your app registered render alongside the preview.
- **Collections** — the media-library records themselves, cross-owner and filterable by collection / owner type / owner id / path prefix. One-click **collection chips** across the top carry each collection's record count and total size (from `/collections/summary`), and clicking a row **drills into the record**: its full metadata plus a signed URL per conversion, with delete when `actions` is on. See [Collections view](/docs/media/dashboard/collections).
- **Uploads** — live resumable sessions, polled every 2s from the session store. Clicking a row **drills into the session**: its full state plus every recorded part, and an abort button when `actions` is on. With the `lucid` session store, the tab needs the `media_upload_sessions` / `media_upload_parts` tables that `node ace configure @adonis-agora/media` publishes a migration for; until `node ace migration:run` creates them, it shows `upload sessions table missing` instead of a list.
- **Upload** — drag-drop / picker, resumable TUS uploads into the chosen disk.
- **Signed out** — when an API call answers `401`, the console goes to the `redirectTo` your `authorize` returned (your app's login), or reloads the page. See [Console access](/docs/media/dashboard/authentication).

## Signed-in user and sign-out

The sidebar footer shows who is signed in, a light/dark toggle and a sign-out button.

Each console has its own fixed accent colour: authkit indigo `#625fff`, durable lime `#a3e635`, telescope magenta `#e879f9`, payments cyan `#22d3ee`, media amber `#fbbf24`, agent rose `#fb7185`, flags emerald `#34d399` and cms orange `#fb923c`. The cms admin is the only console an app can rebrand (`admin.theme` in the `@adonis-agora/cms` config); `accessDenied.accent` colours only the refusal page. Every console has the light/dark toggle in the sidebar footer, remembered per console in each browser.

Without `viewer`, the footer reads `ctx.auth.user` once the request is already authenticated; it never triggers authentication itself. The label is `fullName`, `name` or `email`. Roles come from the user's `role`, `roles` and `globalRoles` (strings, `{ name }` objects or authz role rows `{ role }`) and, when authkit is installed, from the global roles of authkit's per-request identity. The footer shows one of them: the first admin-like one (a name containing `admin`, such as `ADMIN` or `org_admin`), else the first. A `viewer(ctx)` hook replaces all of this.

Pass `viewer` to show something else, or return `null` to hide the user row:

```ts title="config/media_dashboard.ts"
export default defineConfig({
  authorize: (ctx) => ctx.auth.user?.isAdmin === true,
  viewer: (ctx) => {
    const user = ctx.auth.user
    return user ? { label: user.fullName, email: user.email, role: 'admin' } : null
  },
  signOut: '/logout',
})
```

A string `signOut` is a path the button POSTs to, with the request's CSRF token as `_csrf` when shield is installed. `{ href: '/bye' }` renders a link instead. Without `signOut`, the console uses the sign-out that authkit's account console registers. `false` removes the button. Only same-origin paths are accepted.

## Switching between consoles

When the app has other Agora consoles (durable, telescope, payments, the agent console, the authkit
admin), the media brand at the top left becomes a menu that links to them. It lists only the
consoles the current viewer may open: each one is asked through its own `authorize`. With no other
console, or none this viewer may open, the brand stays as it is. There is nothing to configure.

<kbd>Ctrl</kbd>/<kbd>⌘</kbd> + <kbd>K</kbd> opens a search across those consoles. Here, a media
record id opens the record, a collection name opens its records, and a disk name opens its library;
the other consoles answer with their own hits (runs, payments, users).

The menu runs the other consoles' `authorize` on each page load. If yours writes an audit trail,
skip it for these checks: the request carries `ctx.agoraProbe === true` while they run.

```ts title="app/policies/console_access.ts"
export default class ConsoleAccess {
  async authorize(ctx: HttpContext) {
    const allowed = ctx.auth.user?.isAdmin === true
    if (!(ctx as { agoraProbe?: boolean }).agoraProbe) await audit.record('console.open', ctx)
    return allowed
  }
}
```

A console your app mounts by itself can join the menu with `registerAgoraConsole` from a provider's
`boot()`:

```ts title="providers/reports_provider.ts"
import type { ApplicationService } from '@adonisjs/core/types'
import { registerAgoraConsole } from '@adonis-agora/media/dashboard'

export default class ReportsProvider {
  constructor(protected app: ApplicationService) {}

  async boot() {
    await registerAgoraConsole(this.app.container, {
      id: 'reports',
      title: 'Reports',
      icon: 'generic',
      path: '/reports',
      order: 60,
      authorize: async (ctx) => ({ allowed: ctx.auth.user?.isAdmin === true }),
    })
  }
}
```

## MCP tools

When the app registers `@adonis-agora/agent/mcp_provider`, the console's data is also served to
coding agents (Claude Code, Cursor, Claude Desktop) on the app's dev MCP endpoint, `/mcp/agora`.
There is nothing to configure here: the tools follow this console's `authorize`, so whoever can open
the console can use them, and nobody else. A disabled console (`enabled: false`) serves no tools.
The [agent docs](/docs/agent/dev-tools) show how to connect a client.

```sh
claude mcp add --transport http agora http://localhost:3333/mcp/agora \
  --header "Authorization: Bearer $CONSOLE_TOKEN"
```

Reads are listed by default. No tool ever returns a URL to a file, signed or not.

| Tool | What it returns |
| --- | --- |
| `media_list_disks` | The disks the console browses, the default one, and what each supports. |
| `media_list_objects` | One page of a disk under `prefix`: folders and files. Paged with `cursor` and `limit`. |
| `media_get_object` | One object's size, content type and last modified, plus your [object insights](#object-insights). |
| `media_list_uploads` | Resumable uploads in progress (`disk`, `prefix` filters). |
| `media_get_upload` | One upload in progress with its recorded parts. |
| `media_list_collections` | Stored media records, newest first. Filters: `collection`, `ownerType`, `ownerId`, `prefix`. Paged with `cursor` and `limit`. |
| `media_get_collections_summary` | Record count and total bytes per collection. |
| `media_get_media` | One media record by id, with the names of its conversions. |

The two actions, `media_abort_upload` and `media_delete_objects` (at most 100 keys per call), are
hidden until the app opts in with `devTools: { actions: ['media'] }` in `config/mcp.ts`, and they also
need `actions: true` here, like in the console.
