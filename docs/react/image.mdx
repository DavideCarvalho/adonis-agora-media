`<MediaImage>` renders a stored image the way `next/image` does: one `<img>` that

- offers the collection's sizes as **`srcSet`**, so the browser downloads the one the layout needs;
- carries the intrinsic **`width`/`height`**, so the page does not jump when the image arrives;
- **lazy-loads** by default, and with `priority` loads eagerly with high fetch priority;
- paints a **blurred preview** behind itself until it loads.

The server builds the data in one call, `media.library.image(id)`, and the page renders it. Nothing
resizes on the request path: the sizes are the collection's presets, generated at attach.

## 1. Configure the collection

Presets at the widths you want to serve, **eager** so they exist from the attach on, plus the
[placeholder transformer](/docs/media/transformers#image-placeholders-blur-up), which also supplies the
intrinsic size:

```ts
// config/media.ts
{
  name: 'banner',
  acceptsMimeTypes: ['image/jpeg', 'image/png', 'image/webp'],
  conversions: [
    { name: 'sm', width: 640, eager: true },
    { name: 'md', width: 1280, eager: true },
  ],
  transformers: [transformers.placeholder()],
}
```

A preset that keeps the aspect ratio (a lone `width`) is always a candidate. Two kinds never are,
because they are not the same picture at another resolution: a `blur` preset, and one whose fixed
`width`×`height` crops (`cover`) or pads (`contain`) to a different aspect ratio than the original — a
square `thumb` of a landscape photo. The original joins as the widest candidate when browsers can
decode it (JPEG, PNG, WebP, AVIF, GIF — not HEIC or TIFF).

## 2. Build the data on the server

```ts
// a controller
return inertia.render('courses/show', {
  course,
  banner: course.bannerMediaId ? await media.library.image(course.bannerMediaId) : null,
})
```

It returns plain JSON (`ResponsiveImage`):

```ts
{
  src: 'https://…/banner.jpg',                                   // the widest candidate
  srcSet: 'https://…/sm.webp 640w, https://…/md.webp 1280w, https://…/banner.jpg 2400w',
  width: 2400, height: 1200,                                      // intrinsic, EXIF applied
  placeholder: { dataUrl: 'data:image/webp;base64,…', color: '#3a4f6b' },
}
```

| Option | |
|---|---|
| `conversions` | Which presets to offer. Default: every preset of the collection. |
| `generate` | Generate a candidate preset that was never generated (then cached, like `url()`). Default `false`: missing ones are skipped. |
| `expiresIn` | Sign every URL for this long instead of using the public URL — for a private bucket. |
| `url` | `(conversion) => string` — build each URL yourself, e.g. to point at your delivery route. `conversion` is `undefined` for the original. Wins over `expiresIn`. |

<Callout type="info" title="Authorize first">
  Like `url()`, `image()` answers "how", not "who". Check that the caller may see the image before
  building its URLs.
</Callout>

Without `transformers.placeholder()` the result has no `width`/`height` and no `placeholder`, and the
original is not a candidate (its width is unknown) — the presets still make a `srcSet`.

## 3. Render it

```tsx
import { MediaImage } from '@adonis-agora/media-react'

<MediaImage
  image={banner}
  alt={course.title}
  sizes="(max-width: 768px) 100vw, 768px"
  priority
  style={{ width: '100%', height: 'auto' }}
/>
```

| Prop | |
|---|---|
| `image` | The `media.library.image(id)` result. |
| `alt` | Required. `""` for a decorative image. |
| `sizes` | How wide the image renders, so the browser picks from `srcSet` — `next/image` semantics. Without it the browser assumes the full viewport width. |
| `priority` | Above the fold (the LCP image): `loading="eager"` and `fetchPriority="high"`. On React 19 the server also emits a `<link rel="preload">` for it. |
| `fill` | Cover the positioned parent (`position: absolute; inset: 0`) instead of sizing from `width`/`height`. Set `objectFit` in `style`. |
| `placeholder` | `'blur'` (default when there is a preview), `'color'` (dominant colour only) or `'empty'`. |
| `width` / `height` | Override the intrinsic size attributes. |

Every other `<img>` prop passes through, and so does a `ref`.

```tsx
// a card cover whose box the layout decides
<div style={{ position: 'relative', aspectRatio: '16 / 9' }}>
  <MediaImage image={cover} alt="" fill sizes="320px" style={{ objectFit: 'cover' }} />
</div>
```

### How the preview works

Like `next/image`, there is no wrapper element: the preview is the `<img>`'s own background — the
dominant colour, with the tiny WebP on top blurred through an SVG filter — and it is dropped on
`load`. So the component styles like any `<img>`, and:

- **Server rendering** already ships the preview in the markup, before any JavaScript runs.
- An image that **finished loading before hydration** (it never fires `load` again) is detected on mount.
- An image that **fails** keeps the preview instead of showing the broken-image icon.

## The preview on other components

When the `<img>` belongs to another component — a Radix `Avatar`, a CSS background — paint the
preview with `placeholderStyle`:

```tsx
import { placeholderStyle } from '@adonis-agora/media-react'

<AvatarFallback style={user.avatar?.placeholder ? placeholderStyle(user.avatar.placeholder) : undefined}>
  {initials}
</AvatarFallback>
```

Pass `{ width, height }` (the intrinsic size) to keep the picture's proportions in the blur, and
`objectFit` to mirror the element's (`cover` by default).

## Conversions generated before 0.22

Since 0.22 every generated image conversion records its output size in
`record.conversions[name].meta` (`{ width, height }`). For conversions generated earlier, `image()`
derives the width from the preset when the preset pins it down (a lone `width`, or
`cover`/`fill`/`contain` with both sides). Presets it cannot size (`inside`/`outside` with both sides,
a lone `height`) are left out of `srcSet` until regenerated.
