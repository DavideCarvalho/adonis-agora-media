`@adonis-agora/media` is a focused core — owner collections, column attachments, image conversions, a pluggable store and processor, and a testing kit — grown outwards over `@adonisjs/drive` into uploads, transformations, delivery and a management console. Some capabilities are deliberately **not** in it. This page tracks the boundary.

<Callout type="info" title="Why call it out">
  The point of this page is honesty about scope. If you're evaluating the library for a use case below, you'll know whether it's here today — and, for the deferred ones, roughly where it would slot in when it lands.
</Callout>

---

## Beyond the core

- **Resumable / tus uploads** — the [tus](https://tus.io) `1.0.0` protocol with a pluggable session store (in-memory + Lucid). See [Resumable / TUS](/docs/media/uploads/resumable-tus).
- **Direct S3 multipart presign** — the `direct` upload mode (browser uploads straight to S3 via presigned part URLs) alongside `proxy`. See [Upload modes](/docs/media/uploads/upload-modes).
- **A bundled S3 disk** — `disks.s3()` with extended operations (copy / move / deleteMany / list / size / stat) and native multipart, over the optional AWS SDK peer. See [S3 disk](/docs/media/storage/s3-disk).
- **A browser client + React package** — [`@adonis-agora/media-react`](/docs/media/react): `useMediaUpload`, `MediaUploader`, and a framework-free `createMediaUploadClient`.
- **A management console** — the [dashboard](/docs/media/dashboard) ships embedded in `@adonis-agora/media` itself (SPA + JSON API + a [built-in session login](/docs/media/dashboard/authentication)), with cross-owner [collection listing](/docs/media/dashboard/collections) via `MediaStore.list`.
- **A Telescope extension** — a "Media" overview dashboard via [`mediaTelescopeExtension`](/docs/media/integrations/telescope).
- **Transformers + HLS video** — the pluggable [`Transformer` contract](/docs/media/transformers) with a mediabunny-backed HLS transformer (remux to MPEG-TS segments + playlists, WebCodecs injectable), a metadata probe, and the `HlsDeliveryHandler` read path with m3u8 rewriting.
- **Video streaming, HLS and DASH** — [`transformers.dash()`](/docs/media/streaming) packages CMAF (a DASH manifest and an HLS master over the same fMP4 segments, ABR ladders via ffmpeg), `media.access.streamRoute()` serves packages behind the collection's authorization with package-wide signed URLs, and [`useMediaStream`](/docs/media/react/video) plays them in your own `<video>`.

## Still deferred

### More `MediaStore` drivers

The package ships the in-memory and Lucid stores. Additional drivers (e.g. a document/Redis store) aren't built — but the `MediaStore` interface is small and stable, so you can [write your own](/docs/media/stores-and-processors#writing-your-own-store) today.

### More built-in transformers

The [`Transformer` contract](/docs/media/transformers) ships with HLS, DASH and a metadata probe; it was validated against this lineup, and each slots in without contract changes — they just aren't built yet:

- **ImageOptimizeTransformer** — recompress / WebP / strip EXIF via sharp (single replaceable artifact).
- **PlaceholderTransformer** — blurhash/thumbhash from pixel data (metadata-only, like the probe).
- **WatermarkTransformer** — stamp a configured logo (auxiliary asset read through `context.storage`).
- **AudioExtractTransformer** — video → `.m4a` by aac remux; `.mp3` via the pure-JS `@mediabunny/mp3-encoder`.
- **PosterFrameTransformer** — extract a poster frame. Needs a video *decoder*, so it requires an injected WebCodecs implementation (`transformers.hls({ webcodecs })`-style) and throws `TransformerRuntimeMissingError` without one.
- **TranscriptionTransformer** — `.vtt` subtitles via an external async provider.
- **Multi-quality HLS renditions on the WebCodecs engine** — a ladder via mediabunny's fan-out video options. (The ffmpeg engine already ships ladders: `transformers.hls({ engine: engines.ffmpegHls({ ladder: engines.ladders.standard }) })`.)

Also still open from the image side: an **antivirus / scanning hook** in the attach pipeline (it would slot into `attach` before the write).

### Lucid `@media` model decorator

Apps today hold a raw FK (`bannerMediaId`) and resolve records/URLs by hand — a dashboard listing N rows does N resolutions. The planned DX (prior art: `@jrmc/adonis-attachment`) is a decorator in a separate `@adonis-agora/media/lucid` module, keeping Lucid an optional peer:

```ts
class Course extends BaseModel {
  @media({ collection: 'banner' })
  declare banner: MediaAccessor // typed record + conversions + URLs, preloadable, serializable
}
```

The `MediaRecord`/`conversions` shape (including transformer `meta` and multi-artifact `files`) was designed with this accessor in mind; it needs no refactor to support it.

### Named delivery route + Tuyau/Edge helpers

`media.access.deliveryRoute()` is a ready handler (authorization from the collections' `access` rules, resize, signed URLs, HTTP errors), but the app still registers it on a path of its own. Planned (prior art: jrmc v5's `router.attachments()`): an opt-in, **named** mount, a stable route name Tuyau can infer and Edge's `route()` can use, plus an Edge helper for `<img src>` in server-rendered apps.

### A ready upload policy

Collections declare `access.write`, and `media.access.authorize(ctx, 'write', { collection })` applies it, but the upload routes still need your own `DirectUploadPolicy` to call it and to key uploads by the user. Planned: a ready policy that does both from the identity resolver.

### Collection reordering

Ordering is append-only — `attach` always takes the next `order` slot, and `list` returns by `order` ascending. There's no first-party reorder API yet; resequencing means updating the `order` field through your own store access.

## What is in the library today

For contrast, the library ships:

- **Owner collections** — MIME whitelist, single-file replacement, ordering, per-collection disk. See [Collections & Conversions](/docs/media/collections-and-conversions).
- **Column attachments** — the adonis-attachment style, with eager image variants. See [Attachments](/docs/media/attachments).
- **Image conversions** — eager or lazy, cached on the record, via sharp, with focal points and content-aware crops. See [Collections & Conversions](/docs/media/collections-and-conversions#conversions).
- **Responsive images** — `media.library.image()` (srcset, intrinsic size, blur-up), `<MediaImage>` / `<MediaPicture>`, `responsive: true` collections. See [Responsive images](/docs/media/react/image).
- **On-demand resizing and signed delivery URLs** — `?w=`/`?q=` through `MediaDeliveryHandler`, WebP (or opt-in AVIF) by `Accept`, HMAC-signed expiring URLs. See [Delivery](/docs/media/delivery).
- **Metadata stripping** — `stripMetadata: true` removes EXIF/GPS from originals. See [Collections & Conversions](/docs/media/collections-and-conversions#stripping-metadata-gps-exif).
- **Pluggable persistence** — in-memory + Lucid stores with a published migration. See [Stores & Processors](/docs/media/stores-and-processors).
- **Drive-backed storage plus a bundled S3 disk** — reuse your `local` / `s3` / `gcs` disks, or the [S3 disk](/docs/media/storage/s3-disk) with extended operations; signed read URLs included.
- **Uploads for large files** — [proxy and direct-S3](/docs/media/uploads/upload-modes) modes and [resumable TUS](/docs/media/uploads/resumable-tus) sessions.
- **A browser client and an embedded console** — [`@adonis-agora/media-react`](/docs/media/react) and the [management console](/docs/media/dashboard) built into the core package.
- **A testing kit** — in-memory doubles for every seam. See [Testing](/docs/media/testing).
- **Structural diagnostics** — `agora:media:*` events, captured by [Telescope](/docs/media/integrations/telescope) when present.
